Подключение к Kaspersky KUMA 4.6

Токен хранится локально в профиле Firefox и сохраняется после перезапуска и обновления расширения. Логин и пароль KUMA расширение не запрашивает.

Для поиска требуется разрешение POST /api/v3/events. Одних GET-прав недостаточно: POST здесь выполняет SQL-поиск и не изменяет события. Также нужен GET /api/v3/events/clusters и доступ к выбранному кластеру и тенанту.

Поля графа процессов по Event ID

Для каждого типа события задайте поле и значение Event ID, категорию DeviceEventCategory и фактические поля нормализатора. Категория отличает, например, Sysmon 1 от qemu-ga с тем же Event ID. Для Windows 4688 используется Microsoft-Windows-Security-Auditing.

Полезные фильтры

Редактируемый JSON-массив SQL-шаблонов. Значения события подставляются через ${ИмяПоля} с экранированием. Логические группы ${@host}, ${@account}, ${@process}, ${@ip}, ${@file} и другие используют активный профиль полей. timeRange: 5m, 15m, 1h, 24h, 7d или 30d; enabled: false скрывает фильтр.

Проверка IOC в карточке

Кнопка 🐵 появляется рядом с IP, доменом, URL или хешем в карточке KUMA. Выбранный IOC отправляется провайдеру только при нажатии «Проверить». Результат остаётся в меню. Ключи хранятся локально, отдельно от токена KUMA; пустое поле сохраняет прежний ключ.

Проверка подключения

      

      
Сначала сохраните настройки.

      
Если API использует внутренний сертификат, сначала откройте его адрес, подтвердите доверие в Firefox и затем повторите получение кластеров. Ответ 401 в открытой вкладке допустим: токен передаётся только из расширения.

    

    
Только чтение
KumApe разрешает лишь проверку web-сессии и REST-токена, получение кластеров и расширенной схемы полей, поиск событий и чтение ресурса правила корреляции. Изменяющие запросы заблокированы в background-слое.
