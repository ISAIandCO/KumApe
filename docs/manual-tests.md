# Ручная проверка KumApe на KUMA 4.6

## Подготовка

- [ ] `npm test` завершился успешно.
- [ ] `npm run package` создал ZIP.
- [ ] Временное дополнение загружено через `about:debugging`.
- [ ] Firefox доверяет сертификатам Web UI и REST API KUMA.
- [ ] Создан отдельный API-токен: GET `/api/v3/events/clusters` и POST `/api/v3/events` (SQL-поиск), плюс права чтения используемых ресурсов.

## Настройка

- [ ] При первом открытии popup предлагает текущий origin KUMA.
- [ ] Firefox запрашивает разрешение только на Web UI и REST API origin.
- [ ] Настройки сохраняют оба origin, но не показывают токен после ввода.
- [ ] В настройках показаны 17 рекомендуемых related-профилей и отдельные карточки полей графа по Event ID; некорректный JSON и недопустимое имя поля не сохраняются.
- [ ] Для 4688 можно без JSON указать `PID процесса = DeviceCustomString5` и `PID родителя = DeviceCustomString3`; после сохранения фильтр становится применимым.
- [ ] Существующий `processGraph` из версии 0.2.0 один раз переносится в отдельные настройки без потери полей.
- [ ] «Только общие поля» отключает event-specific overrides, а «Вернуть рекомендуемые профили» восстанавливает каталог.
- [ ] После перезапуска Firefox и обновления расширения токен, ключи провайдеров, кластер и профили полей остаются сохранены.
- [ ] «Проверить web-сессию» возвращает текущего пользователя либо понятную ошибку endpoint-а.
- [ ] «Проверить REST API и токен» различает отсутствие токена, сетевую ошибку и HTTP 401/403.
- [ ] «Получить кластеры REST API» показывает доступные storage clusters.
- [ ] При наличии более 250 кластеров загружаются следующие страницы без повторов.
- [ ] «Показать расширенные поля» возвращает схему либо понятный `403` для роли без соответствующего права.

## Текущее событие

Проверить обычное, correlation и вложенное в alert событие.

- [ ] Popup собирает поля карточки из `kuma-id` / `kuma-data`, даже если JSON на странице отсутствует.
- [ ] При открытой области «Исходное событие» расширение отдельно получает Raw-текст.
- [ ] Из нескольких `pre` выбирается именно событие, а не произвольный JSON интерфейса.
- [ ] «Копировать» помещает валидный JSON или Raw без изменений.
- [ ] «Копировать ссылку» возвращает URL текущей вкладки.
- [ ] После перехода к другому событию кнопка «Обновить» заменяет данные.

## Related Events

- [ ] Для `SourceAddress` поиск охватывает `SourceAddress`, `DestinationAddress` и `DeviceAddress`.
- [ ] Для `DeviceHostName` появляется действие по узлу.
- [ ] Для `SourceUserName` / `DestinationUserName` появляется действие по учетной записи.
- [ ] Для `SourceProcessName` / `DestinationProcessName` / `DeviceProcessName` и `FileHash` появляются соответствующие действия.
- [ ] На 4688 командная строка читается из поля, указанного локальным нормализатором (в community-профиле — `DeviceCustomString4`).
- [ ] На Sysmon 1/3/11/22/23 профиль срабатывает только при подходящем `DeviceEventCategory`.
- [ ] На auditd EXECVE/SYSCALL используются поля, указанные в активном профиле.
- [ ] Локальный тестовый профиль действительно заменяет поля выбранной группы и после удаления перестаёт влиять на действия.
- [ ] SQL корректно экранирует значение с `'` и `\`.
- [ ] Период ±5/15 минут, ±1/24 часа строится относительно времени события.
- [ ] API возвращает события из выбранного storage cluster.
- [ ] При 401/403, недоверенном сертификате и недоступном порте показана понятная ошибка.
- [ ] «Открыть в новой вкладке» открывает нативный `/events` KUMA, подставляет SQL и запускает поиск; в URL нет SQL, IP, имени узла или события.
- [ ] Если DOM редактора отличается, поверх `/events` появляется fallback «Копировать SQL», а отдельная страница результатов расширения не открывается.

## Полезные фильтры и процессы

- [ ] Dropdown показывает применимые фильтры первыми; у неприменимых прямо в названии перечислены отсутствующие поля.
- [ ] Для выбранного фильтра видны описание, диапазон, SQL-preview и действия «Найти через API», «Копировать SQL», «Открыть в KUMA».
- [ ] Изменённый или новый шаблон `${ИмяПоля}` сохраняется в настройках, корректно экранирует `'` и появляется в popup; `enabled: false` скрывает его.
- [ ] Кнопка «Вернуть рекомендуемые фильтры» восстанавливает полный встроенный каталог только после общего сохранения настроек.
- [ ] 4688, Sysmon 1 и auditd EXECVE используют отдельное сопоставление полей графа по Event ID.
- [ ] «Родительские и дочерние процессы» открывает canvas-граф всех найденных событий создания процессов того же узла.
- [ ] Рёбра направлены parent→child; PID reuse связывается с ближайшим предшествующим процессом того же узла, GUID имеет приоритет.
- [ ] Работают zoom, pan, drag, force/timeline layout, поиск, режимы «предки»/«потомки», hover и закрепление подсказки правой кнопкой.
- [ ] Двойной клик по узлу с ID события открывает нативный Events KUMA с фильтром этого события.

## Расследования

- [ ] Новое расследование создаётся из события, повторное добавление того же EventID не создаёт дубль.
- [ ] Timeline отсортирован по времени события; описание содержит процесс/пользователя/узел, а не только JSON.
- [ ] Название, статус, теги и заметки переживают перезапуск Firefox.
- [ ] Экспорт JSON и Markdown выполняется только после явного клика.
- [ ] Удаление расследования удаляет его события и не затрагивает остальные расследования.

## Локальный AI

- [ ] Разрешены только localhost, 127.0.0.1 и [::1]; внешний endpoint отклоняется до сетевого запроса.
- [ ] Strict preview исключает Raw, Extra, cookies и ключи; размер и фактические поля показаны до отправки.
- [ ] Redacted маскирует поля и строки с признаками пароля/токена; Full используется только после явного выбора.
- [ ] Endpoint получает запрос только после кнопки «Отправить локальной модели»; облачного fallback нет.
- [ ] Таймаут 120 секунд и HTTP-ошибка показаны в UI без потери текущего диалога.

## IOC

- [ ] IPv4, IPv6, URL, domain, MD5, SHA-1 и SHA-256 распознаются в подходящих полях.
- [ ] До клика на провайдера внешнего запроса нет.
- [ ] Кнопки OpenTIP, VirusTotal и AbuseIPDB открывают новую вкладку с выбранным значением.
- [ ] Кнопка 🐵 появляется в конце названия IOC-поля без открытия popup, в том числе после смены события и в открытом shadow root.
- [ ] Меню не меняет извлекаемые kuma-fields и Raw, не сдвигает карточку вниз.
- [ ] Меню следует за полем при прокрутке; повторный клик, клик снаружи и Escape закрывают его даже после вывода ошибки.
- [ ] API-проверка возвращает отчёт в меню; 401/403/429 отображаются понятно, 404 не называется безопасным результатом.
- [ ] Пустое поле ключа не стирает сохранённый ключ, кнопка удаления удаляет только нужный ключ.
- [ ] На другом порту того же хоста меню не появляется; после смены узла KUMA или отзыва host permission старое меню удаляется.
- [ ] При GET-only правах поиск показывает подсказку про POST `/api/v3/events`; после выдачи этого права поиск повторяется без смены метода.
- [ ] Сохранённый кластер остаётся выбранным при повторном открытии настроек без нажатия «Получить кластеры».

## Correlation rule

- [ ] В correlation event распознается фактическое поле с ID правила.
- [ ] Read-only запрос возвращает ресурс правила.
- [ ] Если endpoint или имя поля изменились, они записаны в таблицу результатов ниже.

## Негативные проверки

- [ ] На вкладке другого сайта расширение не читает DOM и предлагает открыть настроенную KUMA.
- [ ] Background блокирует неизвестный endpoint и методы кроме разрешенных GET/POST.
- [ ] В логах расширения отсутствуют API-токен, Cookie и содержимое Authorization header.
- [ ] В manifest нет `<all_urls>` и обязательного доступа к внешним TI-порталам; optional доступ выдаётся при сохранении ключа провайдера.
