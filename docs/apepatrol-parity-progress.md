# Перенос ApePatrol → KumApe 0.3.0

Ветка: `feat/apepatrol-parity`, база: main после PR #9.
Референс: ApePatrol commit `9b7bff345af4b47060aeb786a10f576cf8705f0a`.

## Реализовано

- 4688: основная пара DeviceCustomString5/DeviceCustomString3, резервная
  DestinationProcessID/SourceProcessID. Пары не смешиваются; hex PID нормализуется.
- Формы настроек обеих пар; миграция старой стандартной пары. Пользовательские
  PID-сопоставления не заменяются автоматически.
- Перенесены исходные renderer/force-layout/spatial-index/filters ApePatrol.
  Адаптер view-model использует KUMA, зависимости от MP SIEM удалены.
- Свободный/временной/пошаговый граф; ПКМ закрепляет карточку, ЛКМ открывает KUMA.
  Поиск родителя/детей у выбранного узла сохраняет цепочку, отсекает несвязанные
  процессы; диапазоны, regex, силы, лимит до 10000 событий за запрос.
- Снимок графа хранится в IndexedDB для переживания выгрузки background.
- Динамический граф расследования из ApePatrol; группировка IP/host/account,
  фильтрация и настройка сил; сравнение событий из ApePatrol.
- Markdown-рендерер ApePatrol в AI; история текущей вкладки; контекст расследования
  с индивидуальной очисткой каждого события.
- Раздел «Процессы», вкладка AI, скачивание JSON, карточки результатов поиска.

## Проверки и ограничения

- 62 автоматические проверки на момент записи, включая пошаговое расширение через
  background, GUID/PID reuse/изоляцию хостов, fallback и Strict-контекст расследования.
- Проверена ограниченная сложность раскладки на 10000 наложенных узлов.
- Сборка, упаковка и проверка воспроизводимости выполняются перед commit.
- Реальная KUMA недоступна. Визуальная проверка также не выполнена: cloud browser
  блокирует localhost, загрузка локального Chromium завершилась таймаутом.
  Автономная страница не запущена из-за ограничения размера browser execution.

## Отличия, которые не следует выдавать за полный паритет

- Начальная пошаговая выборка включает исходный процесс и его непосредственные
  связи; дальнейшие уровни добавляются пользователем из карточек.
- Нет адаптированных к KUMA Table Lists, Knowledge Base и EDR/asset API ApePatrol.
  Для них нужны подтверждённые KUMA API и соответствующие права.
- Граф расследования умеет добавлять результаты поиска по выбранной сущности;
  поиск использует текущие related-профили и ограничен 250 событиями за действие.
- AI использует один открытый чат на исходную KUMA-вкладку, добавляя новые события
  в подготовленный контекст. Автономные tool calls модели ещё не перенесены.

При продолжении не переписывать заново renderer: расширять KUMA-адаптеры.
Сначала выполнить ручные сценарии `docs/manual-tests.md` на доступной KUMA,
затем продолжить интеграции из списка выше.


## Сверка 2026-09-08 — ApePatrol 3.4.14

Эталон: ISAIandCO/ApePatrol, commit 9b7bff345af4b47060aeb786a10f576cf8705f0a.

В 0.3.9 выровнены полный LLM endpoint, общий чат в popup/вкладке/расследовании, локальная история и черновик, JSON-предпросмотр, выбор событий и заметок, поиск и сортировка расследований, удаление объекта, переход к событию. Существующий IndexedDB не меняется.

Дополнительно перенесены сравнение трёх событий с экспортом diff, поиск по нескольким сущностям AND/OR с выборочным добавлением результатов. AI может запросить дополнительный контекст; оператор отдельно разрешает чтение связанных событий KUMA (±15 минут, 50 событий) или прикреплённых объектов расследования, затем проверяет payload перед отправкой.

Остаются отличия: отдельные инструменты ApePatrol для EDR/активов/правил, полное совпадение компоновки popup/настроек и поддержка всех типов прикрепляемых объектов. Это адаптация основных сценариев, а не заявление о полном функциональном или пиксельном совпадении.
