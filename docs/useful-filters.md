# Полезные фильтры

В настройках и списке применения есть две группы:

- **Встроенные** поставляются с расширением и обновляются вместе с ним. Можно отключить фильтр или создать пользовательскую копию.
- **Пользовательские** хранятся отдельно в локальных настройках Firefox. Обновление расширения не заменяет их встроенным набором. Их можно создавать и редактировать через поля формы, импортировать и экспортировать отдельно от токенов и остальных настроек.

Нажмите **Создать фильтр**, заполните название, описание, тип запроса, период, платформу и текст шаблона. Включение задаётся переключателем; идентификатор создаётся автоматически и доступен в дополнительных настройках. Кнопка **Проверить шаблон** показывает подготовленный запрос до подстановки полей события. Для приведённых SELECT-запросов выбирайте **Полный SQL-запрос**.

Отступы, переносы строк и комментарии сохраняются в настройках. Перед применением SQL комментарии `--` и `/* … */` удаляются, пробелы и переносы вне строк сворачиваются. Содержимое строк и quoted identifiers не меняется. Подстановки внутри комментариев игнорируются.

После редактирования или импорта нажмите **Сохранить фильтры**. Эта кнопка сохраняет только фильтры, без проверки адресов KUMA и остальных разделов. Импорт добавляет записи. При совпадении `id` импорт отклоняется целиком: измените идентификатор в файле, чтобы сохранить обе версии. Для замены отредактируйте существующую запись.

При первом обновлении прежний общий список разделяется автоматически. Неизменённые встроенные записи продолжают получать обновления; отключения сохраняются. Изменённые встроенные записи становятся пользовательскими, соответствующие встроенные скрываются. Несовместимые старые шаблоны сохраняются для исправления, но не выполняются; остальные фильтры остаются доступны.

## Формат

```json
[
  {
    "id": "network-summary",
    "name": "Направления соединений исходного IP",
    "description": "Количество событий по адресу, домену, порту и протоколу назначения.",
    "mode": "sql",
    "platforms": [],
    "template": "SELECT DestinationAddress AS dest_ip, DestinationNtDomain AS dest_domain, DestinationPort AS dest_port, TransportProtocol AS protocol, count(ID) AS attempts, uniq(SourcePort) AS source_ports_used FROM `events` WHERE SourceAddress = '${SourceAddress}' GROUP BY DestinationAddress, DestinationNtDomain, DestinationPort, TransportProtocol ORDER BY attempts DESC LIMIT 250",
    "timeRange": "24h",
    "enabled": true
  }
]
```

`mode` имеет два значения:

| Режим | Содержимое `template` | Применение |
| --- | --- | --- |
| `where` (по умолчанию) | Условие, например `DeviceExternalID = '${DeviceExternalID}'` | Прежняя обёртка `SELECT * FROM events WHERE … ORDER BY Timestamp DESC LIMIT …` |
| `sql` | Полный запрос `SELECT …` или `WITH … SELECT …` | После удаления комментариев и нормализации пробелов передаётся без добавления WHERE, сортировки, лимита или колонок |

Полный запрос одинаково используется при копировании SQL, поиске через API и открытии в KUMA. Указанный в нём `LIMIT` имеет приоритет над стандартным лимитом кнопки. Если лимита в запросе нет, расширение его не добавляет. API-результат полного SQL отображается таблицей произвольных колонок в порядке ответа сервера, с копированием JSON. Строка агрегации не выдаётся за исходное событие для расследования.

Подстановки необязательны: можно сохранить статический запрос, в том числе приведённый в запросе пользователя поиск успешных SSH-входов. Он также добавлен во встроенные фильтры. `platforms: ["unix"]` показывает его для Unix-контекста; пустой массив — для любой платформы.

### Подстановки и время

- `${SourceAddress}` и `'${SourceAddress}'` заменяются целым экранированным строковым значением. Известные числовые поля, например `${DestinationPort}`, передаются числом после проверки типа.
- `${@host}`, `${@ip}`, `${@account}` и остальные существующие логические группы дают готовое условие в скобках; используйте их без кавычек в WHERE/HAVING, где допустимо условие.
- Нельзя подставлять часть строки или имени колонки. Комментарии не участвуют в подстановке. Вместо `LIKE '%${Message}%'` используйте `LIKE concat('%', ${Message}, '%')`. Символы `%` и `_` внутри самого значения сохраняют семантику LIKE; для буквального сравнения используйте `=`.
- Если обязательного поля нет, фильтр недоступен с пояснением. Значения события не исполняются как SQL-фрагменты.
- `timeRange`: `5m`, `15m`, `1h`, `24h`, `7d`, `30d`. Это радиус **±** вокруг времени выбранного события. При отсутствии времени используется текущее время. API и новая вкладка используют один способ расчёта абсолютного периода. Период передаётся отдельно, не внедряется в WHERE; условия времени в SQL дополнительно ограничивают выборку.

## Границы SQL

Документация KUMA 4.6 подтверждает SELECT/псевдонимы, FROM `events`, WHERE, GROUP BY, ORDER BY, LIMIT, OFFSET, арифметику и базовые агрегаты (`count`, `avg`, `max`, `min`, `sum`). Для функций строк, дат, массивов, IP и других категорий есть отдельный список поддержки. Псевдонимы не должны содержать пробелы.

Расширение не ограничивает шаблон набором отдельных полей конструктора: выражения, CASE, `uniq`, HAVING, CTE, подзапросы и JOIN могут быть переданы как часть запроса чтения. **Это не гарантия поддержки всего ClickHouse в KUMA.** Допустимость этих конструкций, функций и источников проверяет сервер конкретной версии; в частности, справочник функций оговаривает ограничения условных функций. Пользовательские примеры с CASE/uniq сохранены без переписывания, но требуют проверки на вашем сервере. Используйте `events` как документированный источник событий.

Локальная проверка принимает один SELECT (включая WITH … SELECT), до 64 000 символов. Разрешена завершающая `;`, комментарии и `;` внутри строк. Запросы изменения данных, несколько операторов, INTO/OUTFILE, FORMAT и SETTINGS отклоняются. Это предварительная лексическая проверка, а не собственный парсер ClickHouse; синтаксис и доступ к данным проверяет KUMA. Шаблон WHERE сохраняет прежний предел 4 000 символов. Пользовательский набор — до 100 записей; файл — до 2 МиБ.

В режиме расследования алерта KUMA отдельно ограничивает группировку, агрегаты и псевдонимы. Кнопка KumApe открывает самостоятельную вкладку поиска `/threat-hunting`, а не пытается применить сложный запрос к списку связанных событий алерта.

Импорт принимает обычный JSON-массив (старый формат) либо экспортируемый контейнер `{"kind":"ape-useful-filters","version":1,"dialect":"kuma-sql","filters":[…]}`. Контейнер другого языка отклоняется. ApePatrol использует тот же редактор и механизм хранения через ApeShareCore, но собственный PDQL и `dialect: "maxpatrol-pdql"`; SQL KUMA не переводится автоматически в PDQL.
