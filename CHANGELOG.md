# Changelog

## 0.3.25

- Подключён ApeShareCore 1.7: выключенные категории скрыты в графе, незавершённые профили помечены в редакторе до включения. Сопоставления KUMA не меняются.

## 0.3.24

- Добавлены отдельные профили Windows Security и Linux auditd с условиями сбора, обязательным классификатором, отображением действия/результата и настройкой строкового PID. Новые рекомендации добавляются без перезаписи сохранённых профилей.

- Операции выбранного процесса в пошаговом графе через ApeShareCore 1.6: файлы, сеть, DNS, реестр, доступ к процессам и модули.
- Серверная SQL-пагинация по 25 событий и отдельные настраиваемые профили операций; стартовые профили требуют проверки и включения для конкретного нормализатора.
- Существующие профили запуска 4688 / Sysmon / execve не изменены.

## 0.3.21

- Исправлено размещение встроенных фильтров в списке.
- Создание и редактирование фильтров через поля и переключатели вместо JSON.
- SQL сохраняет исходное форматирование; перед выполнением удаляются комментарии и сворачиваются пробелы вне строк.

## 0.3.20

- Разделены встроенные и пользовательские фильтры; копирование, отдельное сохранение, импорт/экспорт JSON и сохранение старых правок.
- Полный SQL SELECT/WITH, статические запросы, таблица результатов с произвольными колонками; примеры сводки направлений и SSH-входов.
- Полный SQL и период события сохраняются при API-поиске и открытии KUMA.

## 0.3.19

- В настройках и рекомендуемых профилях остаётся один execve: проверка четырёх полей, DestinationProcessID / SourceProcessID. Старые дубли объединяются при обновлении.
- Sysmon использует DestinationProcessID; у блока графа появилась отдельная кнопка сохранения без проверки остальных разделов.

- Исправлен старый профиль Name=execve, использовавший PID audispd вместо запущенного процесса. При выборе профиля PID auditd/audispd больше не принимается за DestinationProcessID.
- Добавлена проверка сохранения исходного узла и связей bash → who при обновлении ApeShareCore.

## 0.3.18

- Добавлен профиль графа по вхождению execve без учёта регистра в любое из полей Message, Name, DeviceEventCategory, DeviceEventClassID; PID — DestinationProcessID, родитель — SourceProcessID. Профиль добавляется в сохранённые настройки при обновлении.
- Совпавший профиль без узла/PID больше не перекрывает следующий подходящий профиль с заполненными полями. Ошибка графа указывает выбранный профиль.

## 0.3.17

- Исправлен PID в стандартном профиле Linux auditd EXECVE: DestinationProcessID вместо DeviceProcessID; PID родителя — SourceProcessID.
- Старый стандартный профиль обновляется автоматически; пользовательские сопоставления сохраняются.

## 0.3.15

- Восстановлена автоматическая регистрация кнопок на страницах KUMA после изоляции background-модулей.
- Пошаговый поиск делит длинные условия на ограниченные запросы и объединяет результаты без повторов.

## 0.3.14

- Общий контроллер AI подключён ко всем чатам; проверяются адрес отправки, актуальность предпросмотра и запрет повторной отправки.
- Хранение снимков графа использует общую проверку схемы и лимиты.
- Длинные AI-вложения сохраняются в рамках бюджета 2 MiB без обрезки по лимитам карточек расследования.

- Подключены общие графы, пошаговый поиск, страница расследований и AI-диалог ApeShareCore 1.2.
- Расследования и чаты используют общую модель и stores workspaces/aiChats. Старые тестовые расследования из схемы v1 автоматически не переносятся.
- Отмена графа прерывает сетевой запрос; снимок восстанавливается без повторной загрузки. SQL, API и mappings KUMA остаются в адаптере.
